# Планы на двоих — Telegram-бот для пар

[@PlansForTwoBot](https://t.me/PlansForTwoBot) — общий органайзер для двоих: календарь важных дат с напоминаниями, общие цели с историей накоплений и список мест «Хочу сходить». Всё работает прямо в чате: кнопки, пошаговый ввод и интерактивные карточки.

Бот бесплатный, без рекламы и платных API. Код открыт, чтобы любой мог проверить, что бот делает с данными, и при желании поднять свой экземпляр.

## Возможности

- **📅 Общий календарь.** Свидания, дни рождения, годовщины, начало отношений, поездки и важные даты. Ежегодные события повторяются сами. Календарь в карточке листается по месяцам, год и месяц выбираются по нажатию на заголовок, по дню видно его события.
- **🔔 Напоминания обоим.** По умолчанию — за 7 дней, за день и в день события, плюс за 2 часа до событий со временем. Дни и час настраиваются. На следующий день после свидания бот предлагает отметить место посещённым, каждые 100 дней отношений — поздравляет.
- **🎯 Цели и накопления.** Машина, отпуск, свадьба — с суммой, сроком и иконкой (из списка или любое своё эмодзи). Пополнение и снятие с комментарием, полная история операций. Партнёру приходит уведомление: кто внёс, сколько, в какую цель и сколько осталось. Это справочный учёт, а не банковский счёт.
- **📍 «Хочу сходить».** Рестораны, выставки, прогулки без даты, с категориями и заметками. «🎲 Куда сходим?» выбирает случайное место.
- **🔗 Цели и события связаны.** «Накопили на поездку → запланировали поездку»: из цели или места можно сразу создать событие, а когда цель достигнута, бот сам предложит запланировать.
- **💬 Уведомления партнёру** о новых и изменённых событиях, целях, пополнениях и местах. Звук можно выключить.
- **✏️ Своё имя.** По умолчанию бот берёт имя из профиля Telegram, но каждый может задать своё — так его будет видеть партнёр.
- **✨ Интерактивные карточки** (виджеты Telegram) для главной, календаря и целей. Если клиент Telegram их не поддерживает, их можно выключить — бот будет присылать обычные сообщения.
- **Удобный ввод.** Данные вводятся по шагам в одной карточке; бот удаляет введённые ответы, чтобы чат оставался чистым. Даты — в мини-календаре или текстом (`14.11`, `14 ноября`, `завтра`), суммы — `15000`, `15 000`, `15к`, `15000 С зарплаты`.

## Какие данные хранит бот

Только то, что нужно для работы:

- **О пользователе:** Telegram ID, имя и username из профиля (Telegram передаёт их с каждым сообщением), своё имя, если задано, настройки, дата регистрации и последнего визита.
- **О паре:** события, цели, операции пополнения, места «Хочу сходить», часовой пояс, валюта и настройки напоминаний.
- **Служебное:** отметки об отправленных напоминаниях (чтобы не было дублей), количество обращений к боту по дням (без содержимого), номера обработанных обновлений Telegram (хранятся 3 дня).

Чего бот не делает:

- Не читает чужие чаты и не работает в группах — только в личной переписке.
- Не передаёт данные третьим сторонам. Единственный внешний адрес в коде — `api.telegram.org`; карточки-виджеты не загружают ничего со сторонних сайтов.
- Не использует аналитику, рекламу и платные сервисы. Зависимость одна — драйвер Postgres [`postgres.js`](https://github.com/porsager/postgres).

Если выйти из пары, данные остаются у партнёра, а у вышедшего пропадает к ним доступ.

## Безопасность и изоляция пар

- **Вход только по коду.** Код из 8 символов (без похожих букв и цифр) действует 48 часов и сгорает после входа партнёра; его можно перевыпустить или отозвать. Перебор ограничен: 5 неверных попыток в час.
- **Не больше двух человек в паре** — это проверяет триггер в базе (`p4t.check_members`), а не только код.
- **Изоляция на уровне Postgres.** Все запросы к данным пары выполняются в транзакции под ролью `p4t_app` (без `BYPASSRLS`) с установленным `p4t.couple`. Политики RLS на всех таблицах пускают только к строкам своей пары, а составные внешние ключи не дают привязать событие к цели или месту чужой пары. Даже ошибка в фильтре кода не приведёт к утечке — это проверяется в тестах.
- **Data API закрыт.** Схема `p4t` не публикуется через REST, у ролей `anon`, `authenticated` и `service_role` нет к ней прав. Доступ есть только у Edge Function через прямое подключение к базе.
- **Вебхук** принимает запросы только с секретным заголовком `X-Telegram-Bot-Api-Secret-Token` (сравнение за постоянное время), повторные `update_id` отбрасываются. Эндпоинты напоминаний и рассылок защищены отдельным секретом. Секреты генерируются при настройке и хранятся в базе, в коде их нет.
- **Виджеты** выводят данные только через `textContent` (без `innerHTML`) и не пересылаются за пределы чата.

## Поддержка

`/support`, а также кнопки «💬 Поддержка» в `/help` и `/settings` ведут в [@KucherAgent](https://t.me/KucherAgent) — бот обращений с антиспамом, на сообщения отвечает человек.

## Админ-панель

Для владельца бота есть `/admin` (или `/stats`). Доступ — только у Telegram ID из `p4t.config.admin_ids`, по умолчанию список пуст. У остальных команда отвечает «Не знаю такой команды», а нажатия админских кнопок игнорируются. Команда `/admin` появляется в меню только в чате админа.

**Статистика — только общие цифры**, без имён, ID, названий событий, целей и сумм:

- пользователи и пары (полные, ждут партнёра, распались), новые за день, неделю и месяц;
- активность: сколько людей заходит за день, неделю и месяц, сколько раз обращаются к боту, графики за 14 дней;
- сегменты пар по активности, «запустили и забыли» (пользовались только в первый день), возврат через неделю;
- воронка: старт → пара → партнёр присоединился → первое событие или цель;
- какими функциями пользуются, сколько отписалось от новостей и заблокировало бота.

По умолчанию статистика приходит интерактивным виджетом с вкладками «Обзор», «Пары», «Функции» и «Всего»: плитки с ключевыми цифрами, столбчатый график за 14 дней (люди или действия, нажми на столбик — увидишь день), цветные полосы сегментов и воронка. Цифры обновляются при каждом открытии виджета. Запрос данных из виджета тоже проверяет права админа, и в виджет передаются только числа. Кнопка «📄 Текстом» показывает ту же статистику обычным сообщением, а если карточки выключены в `/settings`, текстовая версия приходит сразу.

**Рассылки:**

- Получатели выбираются по сегменту: все, полные пары, ждут партнёра, без пары, пустые пары, активные за 7 дней, не заходили 14 или 30 дней, «запустили и забыли».
- Сообщение (текст, фото, видео с форматированием) копируется из чата админа через `copyMessage`. Перед отправкой бот показывает превью и просит подтверждение.
- Отправка идёт в фоне, около 20 сообщений в секунду; если фоновая обработка прервётся, её подхватывает задание `p4t-broadcasts`. По итогам — отчёт, рассылку можно остановить, есть история.
- Под каждой рассылкой есть кнопка «🔕 Не присылать новости», включить их снова можно в `/settings`. Отписавшиеся, заблокировавшие бота и админы рассылку не получают.

## Как это устроено

```
Telegram ──webhook──▶ Edge Function plans-for-two ──postgres.js──▶ Postgres (схема p4t, RLS)
pg_cron (раз в 10 минут) ──pg_net──▶ plans-for-two?cron       ──▶ очередь напоминаний + доставка
pg_cron (раз в минуту)   ──pg_net──▶ plans-for-two?deliver    ──▶ повторная доставка (если есть задания)
pg_cron (раз в минуту)   ──pg_net──▶ plans-for-two?broadcast  ──▶ рассылки (если есть незавершённая)
```

Всё работает на бесплатном тарифе Supabase: Edge Function на Deno, Postgres, pg_cron и pg_net.

### Доставка напоминаний и обработка ошибок

- Webhook сохраняет состояние каждого `update_id`: обработка, завершено, повторная попытка или окончательная ошибка. Если обработчик упал до того, как изменил данные пары, возвращается HTTP 503, и Telegram повторит запрос (не больше 3 попыток). Если данные уже записаны, повтора не будет: так пополнение или цель не задвоятся. Уже обработанный update повторно не выполняется.
- Напоминания сначала сохраняются в `p4t.reminder_deliveries` для **каждого получателя отдельно** в одной транзакции с отметкой события. Статус `sent` устанавливается только после успешного ответа Telegram.
- Временные ошибки Telegram приводят к новым попыткам с увеличивающимся интервалом (до часа). При ответе 429 бот ждёт столько, сколько попросил Telegram (`retry_after`). Ошибка 400 (битое сообщение или чат) считается окончательной, а после 8 неудачных попыток доставка помечается `failed` и больше не повторяется. Заблокировавшим бота повторы не отправляются. При выходе участника из пары старые уведомления ему не доставляются.
- Одновременные запуски воркера захватывают записи через `FOR UPDATE SKIP LOCKED`. В редком случае сбоя между успешной отправкой в Telegram и записью статуса возможна повторная отправка (доставка «хотя бы один раз», а не «ровно один раз»).
- Списки целей и мест загружаются страницами по восемь записей, календарь выбирает события только для нужного месяца. Прежнее скрытое ограничение в 2 000 событий удалено.

## Свой экземпляр

1. Создай бота у [@BotFather](https://t.me/BotFather) и получи токен.
2. Создай проект в [Supabase](https://supabase.com) и примени миграции из `supabase/migrations` по порядку: `supabase db push` или вручную в SQL Editor.
3. Задеплой функцию: `supabase functions deploy plans-for-two --no-verify-jwt`.
4. В Dashboard → Edge Functions → Secrets добавь `PLANS_BOT_TOKEN` с токеном бота. `SUPABASE_URL` и `SUPABASE_DB_URL` Supabase задаёт сам.
5. Один раз открой `https://<project-ref>.supabase.co/functions/v1/plans-for-two?bootstrap`. Функция сгенерирует секреты, сохранит адрес для pg_cron, установит вебхук, команды и описание бота. Повторный вызов заблокирован.
6. Напиши боту `/start`.
7. Чтобы включить админ-панель, укажи свой Telegram ID (несколько — через запятую) и открой `/admin`:
   ```sql
   update p4t.config set value = '<твой Telegram ID>' where key = 'admin_ids';
   ```

Если в описании и ссылках должен быть другой username бота, задай переменную окружения `BOT_USERNAME`.

## Тесты

```bash
cd supabase/functions/plans-for-two
deno check index.ts && deno lint && deno test util_test.ts

# сквозные: нужен локальный Postgres с ролями anon/authenticated/service_role,
# заглушкой схемы cron и применёнными миграциями; Telegram API подменяется в тесте
SUPABASE_DB_URL=postgres://postgres:pg@localhost:5432/p4ttest PLANS_BOT_TOKEN=test \
  deno test -A tests/integration_test.ts
```

Сквозные тесты проверяют весь путь двух пар: создание пары и вход по коду, события, цели и пополнения, «Хочу сходить», виджеты, своё имя и эмодзи, напоминания без дублей, выход из пары. Отдельно проверяется изоляция: чужая пара не видит и не может изменить данные — ни через бота, ни через виджеты, ни напрямую в базе под ролью `p4t_app`. Тест админки проверяет, что обычный пользователь не получает доступ ни через команды, ни через виджет, что в статистике и виджете нет личных данных, а также сегменты, рассылки, отписку и обработку заблокировавших бота.
